// 01 — thesis

The Information Asymmetry

Prediction markets like Polymarket list weather-outcome contracts — "Will NYC exceed 95°F on July 4th?" These markets are priced by participants with varying access to forecast data. The system's premise is simple: better forecast data, processed faster, creates edge.

☁

Multi-Model Ensemble

Ingests GFS, ECMWF, ICON, and HRRR model outputs simultaneously. Ensemble consensus produces a more accurate fair probability than any single model or human intuition. Model disagreement itself is a signal — high disagreement lowers confidence.

⏱

Forecast-to-Market Latency

Weather models update on fixed schedules (hourly to 6-hourly). Markets reprice on participant reaction time. The delta between "model publishes updated probability" and "market reflects it" is the window. The system watches that window continuously.

⚖

Transparent Edge Calculation

No black-box ML. Fair probability is derived from forecast ensemble means, adjusted for model disagreement, threshold distance, and revision direction. Every signal includes a reason code. Every rejection is logged. Fully auditable.

⚠

Paper-First, Always

Live trading is disabled by default and requires explicit opt-in. The system runs paper trades with conservative fill simulation — fills at the ask, accounts for partial fills and liquidity. Prove edge in paper, then consider live.

// 02 — data pipeline

From Forecast to Fill

Five stages, each running on its own loop. Data flows in one direction. Every stage persists its output to Postgres for auditability and backtesting.

01

Market Discovery

run_market_scan · periodic

Scans Polymarket's CLOB API for active weather-related contracts. Parses market titles to extract city, variable type (temp, precip, wind), threshold values, and operators. Persists each market with its ERC-20 YES/NO token metadata.

Polymarket CLOB API Market normalization
02

Forecast Ingestion

run_forecast_poll · ~hourly

For each tracked market location, fetches forecasts from Open-Meteo (GFS, ECMWF, ICON) and NOAA (HRRR, GFS). Raw payloads are preserved. The normalizer computes deltas between consecutive snapshots — tracking how forecasts shift over time and how far values sit from market thresholds.

Open-Meteo API NOAA Weather API Delta tracking
03

Signal Generation

run_signal_loop · ~5 min

The LatencyHunter strategy computes fair probability from the forecast ensemble, compares it to the current market-implied probability, and calculates edge in basis points. Signals are generated with a direction (BUY_YES, BUY_NO, or HOLD), confidence score, and explicit reason code.

# fair probability derivation fair_p = ensemble_mean(models) + disagreement_adj(model_spread) + threshold_adj(distance_to_threshold) + revision_adj(forecast_delta_direction) edge_bps = (fair_p - market_p) * 10_000
LatencyHunterV1 Confidence scoring Reason codes
04

Risk Gate

inline · per-signal

Every approved signal passes through the risk manager before execution. Checks daily loss limits, total exposure, per-market concentration, spread width, data freshness, and market close proximity. Any rule violation rejects the trade and logs a RiskEvent.

5 rule categories Position limits Data freshness
05

Execution & P&L

run_paper_trader · on signal

Paper executor simulates conservative fills — buys fill at the ask, not mid. Partial fills modeled against available liquidity. Positions are tracked per-market per-outcome with realized and unrealized P&L. The P&L engine marks to market continuously and produces daily reports.

Conservative fills FIFO cost basis Daily reporting

// 05 — automation

Runs Itself

Five independent job loops, containerized with Docker Compose, orchestrated by cron or a lightweight scheduler. Once configured, the system discovers markets, ingests forecasts, generates signals, and paper-trades without human intervention.

every 6 hours

Market Scanner

Discovers new weather contracts on Polymarket. Parses market metadata, extracts locations and thresholds, persists to the markets table. Old markets are deactivated when contracts close.

every 60 minutes

Forecast Poller

Fetches latest model runs from Open-Meteo and NOAA for all tracked locations. Normalizes, computes deltas, flags significant changes. Keeps raw payloads for audit.

every 5 minutes

Signal Loop

Evaluates all active markets against latest forecast and price data. Runs LatencyHunterV1 strategy, generates signals with direction, edge, and confidence. Only APPROVED signals proceed.

on approved signal

Paper Trader

Receives approved signals, runs risk checks, simulates execution. Updates positions, records fills, tracks P&L. All in paper mode until explicitly toggled.

daily at 00:00 UTC

Report Generator

Aggregates daily trades, P&L, win rate, risk events. Exposes via /reports/daily API endpoint. Future: push to Slack or email.

// 06 — economics

Path to Passive Income

The system is designed to run autonomously once validated. Here's the honest breakdown of what makes this viable and what the open questions are.

Why This Can Work

  • Weather forecasts are freely available, high-quality numerical data — not rumors or sentiment
  • Prediction markets are still inefficient; most participants trade on vibes, not ensemble models
  • Polymarket weather markets have real volume but limited sophisticated competition
  • The edge is structural: forecast models update on fixed schedules, humans reprice slowly
  • Operating cost is near zero — Docker container on a $5-20/mo VPS, free API data sources
  • Strategy is pluggable — LatencyHunterV1 is the first strategy, not the last
  • Conservative risk limits mean the system survives its own mistakes during learning
  • Backtest framework provides evidence before real capital deployment

Open Questions (Honest)

  • Are Polymarket weather markets liquid enough to absorb consistent order flow?
  • Does the latency edge survive after spreads and fees are accounted for?
  • Will market efficiency improve as prediction markets mature, eroding edge?
  • Are there enough weather contracts to diversify across, or is this seasonal?
  • Can the system distinguish genuine forecast shifts from model noise?
  • How does the system perform in low-volatility weather periods (clear skies for weeks)?
The thesis is testable. Paper trading with conservative fills gives a realistic P&L trajectory without risking capital. The backtest engine replays historical data with the same strategy and risk rules. If the numbers work in paper, the path to live is a single config flag. If they don't, the strategy gets refined or replaced — with zero capital lost.

Development Phases

The codebase is structured and production-ready. The core framework is built. What remains is wiring the logic and validating the thesis.

Phase 1 — Current

Foundation & Paper Trading

  • Complete adapter integrations (API clients)
  • Wire LatencyHunterV1 fair-probability formula
  • Implement risk manager rule enforcement
  • Paper executor with conservative fills
  • Run continuous paper trading & collect data
Phase 2 — Validation

Backtest & Refinement

  • Backtest replay engine over historical data
  • Analyze win rate, drawdown, Sharpe ratio
  • Tune thresholds (edge, confidence, spread)
  • Add notification pipeline (Slack, email)
  • Deploy to VPS with monitoring
Phase 3 — Scale

Live Trading & Expansion

  • Enable live execution (Polymarket CLOB auth)
  • Gradual position sizing ramp-up
  • Additional strategies beyond latency hunting
  • Multi-market expansion (beyond weather)
  • Real-time dashboard for monitoring
